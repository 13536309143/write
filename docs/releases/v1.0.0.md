# GlyphWeave v1.0.0 — First complete experiment / 首次完整实验

This release publishes one model trained from random initialization with seed 42. It includes the default 7,820,044-parameter architecture, 80 completed Windows CUDA epochs, and the existing complete independent test report. It does not claim baseline superiority or completed ablation studies.

本版本发布随机种子为 42、从随机初始化训练的单个模型，采用默认 7,820,044 参数结构，已完成 Windows CUDA 的 80 轮训练，并附已有的完整独立测试报告。不宣称优于基线或已完成消融实验。

## Recognition / 识别

Clone the matching source release, install dependencies as documented in the README, and extract the inference ZIP into the project root. Then run:

克隆对应版本源码、按 README 安装依赖，将推理 ZIP 解压到项目根目录，然后运行：

```bash
.venv/bin/python predict.py path/to/glyph.png --checkpoint glyphweave-v1.0.0-inference/best.pt
.venv/bin/python app.py --checkpoint glyphweave-v1.0.0-inference/best.pt
```

On Windows, replace `.venv/bin/python` with `.\.venv-win\Scripts\python.exe`. Single-image recognition does not require the dataset. Complete evaluation requires the entire `data/processed/` directory with the matching index:

Windows 将 `.venv/bin/python` 替换为 `.\.venv-win\Scripts\python.exe`。单图识别不需要数据集；完整评估需要包含匹配索引的整个 `data/processed/` 目录：

```bash
.venv/bin/python evaluate.py --checkpoint glyphweave-v1.0.0-inference/best.pt --output runs/release_v1_test_metrics.json
```

## Limits and provenance / 局限与来源记录

The 80-epoch training schedule is complete. The full checkpoint preserves state for inspection and recovery, but increasing `epochs` on resume is rejected by the current trainer. Additional training requires a separately defined experiment. Not all RNG states were saved, so recovery is not bitwise reproducible.

80 轮训练调度已经完成。完整检查点保留状态供检查与恢复，但现有训练器会拒绝恢复时增加 `epochs`；继续增加训练预算需要另行定义实验。未保存全部 RNG 状态，恢复不保证逐位复现。

The original logs do not record the training commit or full runtime versions, and the existing test JSON does not identify its evaluation checkpoint. File hashes added to the release identify the files being distributed; they do not retroactively reconstruct those missing records. One seed, no matched-budget baseline, no ablations, no timing benchmark, and no external-photo benchmark were completed. Candidate scores are uncalibrated, and letter/digit confusions remain substantial.

原始记录没有训练代码提交与完整运行库版本，已有测试 JSON 也没有记录评估检查点的身份。发布时添加的文件哈希用于标识当前分发文件，不补造这些缺失记录。仅完成单个随机种子，未完成相同预算基线、消融、计时或外部照片基准。候选分数未经校准，字母与数字的混淆仍较明显。

## Rebuild packages / 重新打包

With the original experiment folder and its analysis figures available, maintainers can rebuild into a new output directory:

维护者保留原始实验目录及分析图片后，可重新打包到新的输出目录：

```bash
.venv/bin/python scripts/build_release.py --version v1.0.0 --output work/releases/v1.0.0-rebuilt
```

ZIP hashes identify a particular build; regenerated archives may have different hashes. The builder never modifies the original checkpoint or packages the dataset.

ZIP 校验值对应具体打包产物，重新打包可能产生不同校验值。打包程序不修改原始检查点，也不将数据集放入模型包。
